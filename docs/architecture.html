Python Compiler — Architecture & Workflow

A hand-written compiler that translates Python source (targeting CPython 3.14) into .pyc bytecode files. The project also supports HTML/Jinja2 and CSS.

End‑to‑End Pipeline Overview

Phase 1 Lex & Parse → Phase 2 Build AST → Phase 3 Semantic Analysis → Phase 4a Bytecode Generation → Phase 4b Serialise .pyc

Phase 1 — Lexing & Parsing

ANTLR 4.13.2

The source file is fed through the ANTLR-generated PythonLexer (tokeniser) which produces a CommonTokenStream. The PythonParser then builds a Concrete Syntax Tree (CST) using the grammar rules defined in grammars/PythonParser.g4. 

// App.processFile() — relevant snippet
CharStream input     = CharStreams.fromFileName(path);
PythonLexer lexer    = new PythonLexer(input);
CommonTokenStream tokens = new CommonTokenStream(lexer);
PythonParser parser  = new PythonParser(tokens);
parser.addErrorListener(new CustomErrorListener());
ParseTree tree       = parser.prog();   // ← CST built here

Key files: PythonLexer.java, PythonParser.java, PythonLexerBase.java (custom indentation, brace tracking, NEWLINE handling), CustomErrorListener.java.

Phase 2 — AST Construction

~18 specialised visitors

The CST is walked by a family of visitor classes, each responsible for a single grammar domain. Every visitor creates or dispatches to create hand‑crafted AST nodes (in src/ast/). The symbol table is populated inline during this phase. 

// CompoundStatementVisitor acts as the dispatcher
switch (ctx) {
    case AssignmentStatementContext a  → visitAssignmentStatement(a);
    case IfStatementContext i           → build new IfStatement(...);
    case ForLoopStatementContext f      → new ForLoopVisitor().visit(f);
    case FunctionDefinitionContext fn   → enterScope(); build new FunctionDefinition(...); exitScope();
    case AtomExpressionContext a        → new AtomExpressionVisitor().visit(a);
    case ReturnStatementContext r        → new ReturnStatementVisitor().visit(r);
    case ImportStatementContext i        → build new ImportStatement(...);
    case GlobalStatementContext g        → build new GlobalStatement(...);
    default                               → UniversalPythonVisitor().visit(ctx);
}

Key files: ProgramVisitor.java, StatementVisitor.java, CompoundStatementVisitor.java, AssignmentStatementVisitor.java, AtomExpressionVisitor.java, AtomVisitor.java, ConditionVisitor.java, ForLoopVisitor.java, ArithmeticExpressionVisitor.java, ComplexExpressionVisitor.java, ReturnStatementVisitor.java, FunctionParametersVisitor.java, ArgumentListVisitor.java, ArgumentVisitor.java, KeyValueVisitor.java, TemplateLiteralVisitor.java, UniversalPythonVisitor.java, and all ast/ node classes.

Phase 3 — Semantic Analysis

Rule-based walker

The SemanticAnalyzer walks the entire AST and applies a set of SemanticRule implementations to every node. Errors are collected and printed but do not halt compilation.

RuleWhat it checks
TypeRuleType inference; detects mismatches (e.g. string + int)
UndefinedVariableRuleFlags Name nodes not found in symbol table
UndefinedFunctionRuleFlags FunctionCall to unknown functions (40+ builtins whitelisted)
DuplicateFunctionRuleFlags duplicate def names
ReturnOutsideFunctionRuleFlags return at module level
// SemanticAnalyzer.analyze()
for (SemanticRule rule : rules) {
    rule.apply(node, symbolTable, reporter);
}
walk(node.getChildren(), reporter);  // recurse

Key files: SemanticAnalyzer.java, SymbolTable.java, SymbolTableManager.java, SymbolEntry.java, ErrorReporter.java, rules/*.java.

Phase 4a — Bytecode Generation

Polymorphic dispatch on AST nodes

Every AST node class implements generateBytecode(CodegenContext ctx). The top-level CPythonBytecodeGenerator creates a CodegenContext and calls program.generateBytecode(ctx), which recursively emits instructions into the context's instruction list.

Key data structures:

  • PythonCodeObject — mirrors CPython's PyCodeObject: co_code (byte[]), co_consts, co_names, co_varnames, co_stacksize, etc.
  • PythonInstruction — record(PythonOpCode opcode, int arg); each is 2 bytes in the final co_code
  • CACHE_COUNTS — a map specifying how many inline CACHE(0) entries follow each opcode (e.g. BINARY_OP → 5, CALL → 3, LOAD_GLOBAL → 4)

CodegenContext — Central State Machine

The CodegenContext holds:

  • Current instruction list & code object
  • ConstantPoolManager — deduplicating constant list → co_consts
  • NameManager — manages co_names, co_varnames, co_freevars, co_cellvars
  • LabelManager — two-pass label resolution + jump backpatching
  • StackDepthCalculator — simulates stack to determine co_stacksize
  • SavedState stack — for entering/leaving function scopes (save & restore all state)
  • enclosingLocalsStack — for detecting closures

Scope-aware variable access

// CodegenContext.storeVariable(name)
if (inFunction) {
    if (globalDeclared)     → STORE_GLOBAL
    else if (isCellVar)     → STORE_DEREF
    else                    → STORE_FAST
} else {
                            → STORE_NAME
}

// CodegenContext.loadVariableForCall(name)
// Sets LSB=1 in LOAD_GLOBAL arg to push NULL before the callable
→ LOAD_GLOBAL(idx << 1 | 1)
→ LOAD_FAST(idx)
→ LOAD_DEREF(derefIdx)

Function-scope nesting (closures)

// Save current state, create new code object
ctx.pushFunctionScope(funcName, filename, line);
    // ... emit function body ...
    loadConstant("NONE_PLACEHOLDER"); emitReturnValue();
    funcCode = ctx.popFunctionScope();
    // popFunctionScope():
    //   • fixCellVars() — patches LOAD_FAST→LOAD_DEREF for cell vars
    //   • inserts MAKE_CELL + COPY_FREE_VARS
    //   • restores parent scope state

// Emit closure tuple if the child has free variables
for (String fv : funcCode.co_freevars) {
    loadVariable(fv);         // LOAD_FAST or LOAD_DEREF in parent scope
}
emitBuildTuple(freevars.size());
emitLoadConst(funcCode);      // ← the nested code object
emitMakeFunction(0);
if (!funcCode.co_freevars.isEmpty())
    emitSetFunctionAttribute(8);  // closure marker

Loop with inline listcomp

// ListComprehension.generateBytecode(ctx)
emitBuildList(0);                       // push []
loadVariable(iterableName);             // push iterable
emitGetIter();                          // replace iterable with iterator
markLabel(loopStart);
emitForIter(loopEnd);                   // pushes value, or None + jump to end
storeVariable(loopVarName);
// ... condition + yield expression ...
emitListAppend(2);
emitJumpBackward(loopStart);
markLabel(loopEnd);
emitEndFor();                            // pop None sentinel
emitPopIter();                           // pop iterator
// result list left on TOS for assignment

Key files: CPythonBytecodeGenerator.java, CodegenContext.java, ConstantPoolManager.java, NameManager.java, LabelManager.java, StackDepthCalculator.java, PythonOpCode.java, PythonInstruction.java, PythonCodeObject.java, and every ast/*.java file (each has generateBytecode).

Phase 4b — Serialisation (.pyc)

Python marshal format v4

The PycFileWriter writes a 16‑byte header followed by a marshalled PythonCodeObject tree. 

// .pyc file = 16-byte header + marshal body
Bytes [0:4]  = magic 0x0A0D0E2B              // Python 3.14 little-endian
Bytes [4:8]  = flags = 1                         // UNCHECKED_HASH (no source validation)
Bytes [8:16] = timestamp (8 bytes, ignored)

// MarshalWriter — serialises recursively:
TYPE_CODE_REF (0xe3)
  ├── argcount, posonlyargcount, kwonlyargcount    // int32 × 3
  ├── stacksize, flags                              // int32 × 2
  ├── co_code                                       // TYPE_STRING_REF
  ├── co_consts                                     // TYPE_SMALL_TUPLE_REF
  │     ├── Nested code objects (functions)         // → recursive TYPE_CODE_REF
  │     ├── Integers, Floats, Strings, Booleans, None
  ├── co_names                                      // TYPE_SMALL_TUPLE_REF
  ├── localsplusnames                               // TYPE_SMALL_TUPLE_REF
  ├── localspluskinds                               // TYPE_STRING_REF (byte flags)
  ├── filename, name, qualname                      // TYPE_SHORT_ASCII_REF
  ├── firstlineno                                   // int32
  ├── linetable                                     // TYPE_STRING_REF
  └── exceptiontable                                // TYPE_STRING_REF

Key files: PycFileWriter.java, MarshalWriter.java.

Key Design Decisions

DecisionRationale
Visitors for CST→AST, methods on AST nodes for codegen Double‑dispatch. ANTLR visitors handle grammar‑specific logic during tree conversion; each AST node knows how to emit its own bytecode (polymorphism), avoiding a monolithic switch.
Symbol table populated during AST construction No separate pass needed. The visitor building the AST already knows what symbols are being defined (function names, parameters, globals) and can enter/exit scopes immediately.
Dynamic type inference in AssignmentStatementVisitor Keeps the symbol table useful for semantic checks without requiring a full Hindley‑Milner type system. Infers Integer, Float, String, Boolean, List, Dict.
CodegenContext with SavedState stack Encapsulates all mutable codegen state (instructions, pools, labels, scope flags). Functions push/pop their own state, allowing clean nesting without parameter threading.
Inline cache entries (CACHE opcode) Matches CPython 3.12+ instruction format exactly. Affects jump offset calculations in LabelManager.
Jump backpatching with EXTENDED_ARG Two‑pass approach: emit jumps with arg=0, then resolve at finalisation. Insert EXTENDED_ARG prefix instructions when the jump offset exceeds 255 (2‑byte limit).
UNCHECKED_HASH .pyc header (flags=1) Python 3.12+ supports hash‑based .pyc files. Using flag=1 avoids needing to compute _imp.source_hash() (SipHash) from Java, which is impractical. The .pyc loads without source validation.
NONE_PLACEHOLDER sentinel None can't be a Java String in the constant pool. A sentinel string "NONE_PLACEHOLDER" is converted to TYPE_NONE ('N') during marshalling.
