مترجم بايثون — البنية وسير العمل

مترجم مكتوب يدويًا يحلّل كود بايثون ويُجري التحليل الدلالي ثم يستخرج سياق التشغيل (ContextExtractor) ويحوّل قوالب Flask/Jinja2 إلى HTML ثابت. يدعم المشروع أيضًا HTML/Jinja2 و CSS، ويمكنه تقديم المخرجات عبر خادم ويب مدمج (--serve) يوفّر واجهة CRUD عامة (/api/<collection>) لأي قائمة من القواميس على مستوى أعلى ملف — وليس فقط products.

المرحلة 1 — التحليل المعجمي والنحوي

ANTLR 4.13.2

يُمرَّر الملف المصدر عبر PythonLexer المُولّد بواسطة ANTLR (المفوّت المعجمي) الذي ينتج CommonTokenStream. ثم يبني PythonParser شجرة الصياغة الملموسة (CST) وفق قواعد القواعد النحوية المعرّفة في grammars/PythonParser.g4. 

// App.processFile() — مقتطف ذو صلة
CharStream input     = CharStreams.fromFileName(path);
PythonLexer lexer    = new PythonLexer(input);
CommonTokenStream tokens = new CommonTokenStream(lexer);
PythonParser parser  = new PythonParser(tokens);
parser.addErrorListener(new CustomErrorListener());
ParseTree tree       = parser.prog();   // ← تُبنى CST هنا

ملفات أساسية: PythonLexer.java, PythonParser.java, PythonLexerBase.java (معالجة مخصصة للمسافات البادئة، وتتبّع الأقواس، والتعامل مع NEWLINE)، CustomErrorListener.java.

المرحلة 2 — بناء AST

حوالى 32 زائرا متخصصا

تُمسَح CST بواسطة عائلة من أصناف الزوار، وكل زائر مسؤول عن مجال نحوي واحد. كل زائر ينشئ —أو يوزّع لإنشاء— عقد AST مكتوبة يدويًا (في src/ast/). ويُملأ جدول الرموز ضمنيًا خلال هذه المرحلة. 

// يعمل CompoundStatementVisitor كموزّع
switch (ctx) {
    case AssignmentStatementContext a  → visitAssignmentStatement(a);
    case IfStatementContext i           → build new IfStatement(...);
    case ForLoopStatementContext f      → new ForLoopVisitor().visit(f);
    case FunctionDefinitionContext fn   → enterScope(); build new FunctionDefinition(...); exitScope();
    case AtomExpressionContext a        → new AtomExpressionVisitor().visit(a);
    case ReturnStatementContext r        → new ReturnStatementVisitor().visit(r);
    case ImportStatementContext i        → build new ImportStatement(...);
    case GlobalStatementContext g        → build new GlobalStatement(...);
    default                               → UniversalPythonVisitor().visit(ctx);
}

ملفات أساسية: ProgramVisitor.java, StatementVisitor.java, CompoundStatementVisitor.java, AssignmentStatementVisitor.java, AtomExpressionVisitor.java, AtomVisitor.java, ConditionVisitor.java, ForLoopVisitor.java, ArithmeticExpressionVisitor.java, ComplexExpressionVisitor.java, ReturnStatementVisitor.java, FunctionParametersVisitor.java, ArgumentListVisitor.java, ArgumentVisitor.java, KeyValueVisitor.java, TemplateLiteralVisitor.java, UniversalPythonVisitor.java، وجميع أصناف العقد في ast/.

المرحلة 3 — التحليل الدلالي

ماسح قائم على القواعد

يمرّ SemanticAnalyzer على كامل AST ويطبّق مجموعة من القواعد SemanticRule على كل عقدة. كل مخالفة تُحمَّل كـاستثناء مسمّى (semantic/errors/*.java)، ويُبلّغ عنها سطر الأوامر بالصيغة Semantic error detected "TypeError": …. يوجد مثال قابل للترجمة لكل نوع خطأ داخل samples/<ErrorName>/.

القاعدةما تفحصهالخطأ المرفوع
TypeRuleاستدلال الأنواع؛ يكتشف التباينات (مثل سلسلة + عدد)TypeError
UndefinedVariableRuleيرصد عقد Name غير الموجودة في جدول الرموزUndefinedVariableError أو ScopeError
UndefinedFunctionRuleيرصد استدعاءات FunctionCall لدوال غير معروفة (يُسمح بـ 30 دالة مدمجة)UndefinedFunctionError
NotIterableRuleيرصد التكرار for-in على قيمة غير قابلة للتكرارNotIterableError
DuplicateFunctionRuleيرصد تكرار أسماء defDuplicateFunctionError
ReturnOutsideFunctionRuleيرصد return على المستوى الأعلى (يراعي نطاق الدوال)ReturnOutsideFunctionError

إذًا فالقواعد الست تُنتج سبعة من الأخطاء المسمّاة الثمانية. أما الثامن، MissingFlaskVariableError، فليس قاعدة — بل يرميه semantic/jinja/FlaskTemplateChecker.java عندما يكون متغير قالب لم يُمرَّر إلى render_template. لهذا يحتوي samples/ على 9 مجلدات: مجلد لكل نوع خطأ (8) بالإضافة إلى CombinedErrors/، وهو ملف واحد يثير عدة أخطاء معًا كعرض توضيحي. 

// SemanticAnalyzer.walk() — يطبّق كل قاعدة على العقدة ثم يعاود حسب النوع
for (SemanticRule rule : rules) {
    rule.apply(node, symbolTable, reporter);
}
switch (node) {                  // Program, Statement, If, While, ForLoop, FunctionDef…
    case IfStatement i         → walk(i.getStatement(), reporter);
    case FunctionDefinition f  → walk(f.getFunctionBody(), reporter);
    default                    → // ورقة
}

ملفات أساسية: SemanticAnalyzer.java, SymbolTable.java, SymbolTableManager.java, SymbolEntry.java, ErrorReporter.java, rules/*.java, errors/*.java.

المرحلة 4 — استخراج السياق وتوليد HTML وواجهة الخادم

وضع مشروع Flask

يمرّ ContextExtractor على AST بايثون ويستخرج البيانات اللازمة لنسج القوالب (دوال المسارات، ومتغيرات السياق، وأهداف url_for، وبيانات القوائم/المجموعات). ثم يقوم JinjaRenderer بتحويل كل قالب (بالاعتماد على عقدة HtmlContent) إلى HTML ثابت، يكتبه OutputWriter في output/ مع الملفات المساندة (app.py، styles.css، script.js، templates/). وتُكتب التقارير (التقرير الدلالي، سجل التوليد، ونسخ AST بصيغة JSON) في compiler_output/. 

// processFlaskProject() — مقتطف ذو صلة
ContextExtractor extractor = new ContextExtractor();
Map<String, Object> context = extractor.extract(program);       // المرحلة 4
Map<String, String> routes   = extractor.extractRoutes(program);

JinjaRenderer renderer       = new JinjaRenderer(context, templateMap, routes);
String renderedHtml           = renderer.render(htmlContent);
outputWriter.writeHtmlFile(outputName, renderedHtml);            // المرحلة 5

في وضع التشغيل (--serve) يُعاد توليد مجلد output/ باستمرار بواسطة ProjectWatcher عند أي تغيير في الملفات المصدرية، ويقدّم CompilerWebServer الصفحات على نفس الأصل (بدون CORS). أما عند استدعاء ملف واحد (غير Flask) فتُتخطى مرحلة النسج — تُطبع شجرة AST والتحليل الدلالي فقط؛ وتُكتب ملفات .html/.j2/.css في مجلد محلي generated/.

واجهة CRUD العامة

يكتشف الخادم المجموعات القابلة للتحرير من السياق المترجم: أي متغير على مستوى أعلى ملف تكون قيمته قائمة قواميس تحمل كل منها مفتاح "id" رقميًا (مثل products و posts و books). كل مجموعة تحصل على نقطة نهاية خاصة بها /api/<collection>:

النقطةالطريقةالإجراء
/api/<collection>GETسرد كل السجلات (مصفوفة JSON مع الحفاظ على الأنواع)
/api/<collection>POSTإنشاء سجل (id = أكبر قيمة + 1) ← 201
/api/<collection>/<id>GETجلب سجل واحد
/api/<collection>/<id>PUTتحديث الحقول من النموذج ← 200
/api/<collection>/<id>DELETEحذف سجل ← 204

يُبقي PythonDataStore ملف app.py مصدرًا وحيدًا للحقيقة: كل تعديل يُعاد كتابته في الحرفية المطابقة، ثم يستدعي CompilationSnapshot.rerender() لإعادة نسج القوالب بـسياق حي مدمج (كل المجموعات القابلة للتحرير من مخازنها، والباقي من آخر ترجمة كاملة). تُحوَّل الأعداد الصحيحة إلى أعداد صحيحة في مخرجات JSON/النسج، بينما تحافظ الأعداد العشرية والقيم المنطقية والسلاسل على نوعها. أما بقية السياق (قواميس عادية، قوائم سلاسل، قيم رقمية) فتبقى للقراءة فقط. وتُبلغ الأخطاء بصيغة JSON (404/400/405/500)، ويبث تيار SSE على /events أحداث regenerated أو compiler-error.

ملفات أساسية: generator/ContextExtractor.java, generator/JinjaRenderer.java, generator/OutputWriter.java, app/CompilerWebServer.java, app/PythonDataStore.java, app/DataRecord.java, app/CompilationSnapshot.java, app/ProjectWatcher.java.

قرارات التصميم الرئيسية

القرارالمبرّر
زوار لتحويل CST→AST ومولّدات تعمل على عقد AST إرسال مزدوج. زوار ANTLR يتكفلون بالمنطق الخاص بالقواعد أثناء التحويل؛ أما مستخرج السياق ومولّد Jinja فيمرّان على AST النهائي بدلًا من switch عملاق.
ملء جدول الرموز أثناء بناء AST لا حاجة لمرحلة منفصلة. الزائر الذي يبني AST يعرف أصلاً ما هي الرموز المعرّفة (أسماء الدوال، المعاملات، العموميات) ويدخل/يخرج النطاقات فورًا.
استدلال الأنواع الديناميكي في AssignmentStatementVisitor يجعل جدول الرموز مفيدًا للفحوص الدلالية دون الحاجة إلى نظام أنماط كامل (Hindley-Milner). يستنتج Integer و Float و String و Boolean و List و Dict.
فصل استخراج السياق عن النسج ContextExtractor يجمع بيانات المسارات ومتغيرات السياق في تمريرة واحدة؛ وJinjaRenderer يستهلكها فقط. هذا الفصل يسهّل إعادة نسج HTML بعد أي تغيير في البيانات: يحتفظ CompilationSnapshot بآخر ترجمة ناجحة ويستدعي rerender(liveContext) دون إعادة تحليل معجمي/نحوي.
app.py هو مصدر الحقيقة الوحيد في بيئة الويب (PythonDataStore) تُكتب تعديلات CRUD على أي مجموعة في الحرفية المطابقة من app.py ثم يُعاد نسج القوالب عبر المترجم — لا يوجد نموذج بيانات ثانٍ يجب مزامنته، وتحافظ الأنواع (أرقام، منطقيات، سلاسل) على سلامتها في دورة الذهاب والإياب.
اكتشاف المجموعات القابلة للتحرير لا كتابتها بشكل صلب يفحص الخادم السياق المترجم ويكشف /api/<collection> لكل متغير قيمته قائمة قواميس تحمل "id" رقميًا (products, posts, books, ...). لا يوجد أي حقل مكتوب بشكل صلب، وتبقى البيانات غير القوائم للقراءة فقط.
إعادة النسج بعد تعديل الواجهة بسياق مدمج بعد أي كتابة من المتصفح، تُدمج كل المجموعات القابلة للتحرير فوق سياق اللقطة قبل إعادة النسج، حتى تُولَّد القوالب التي تقرأ عدة مجموعات (مثل students + teachers) بشكل متسق في تمريرة واحدة.
